# Low-Level Design (LLD) in C++

This repository is dedicated to practicing **Low-Level Design (LLD)** concepts in **C++**, with a focus on software engineering interview preparation.

The goal is to build a strong understanding of object-oriented design and learn how to apply design principles and patterns to real-world problems.

## Topics Covered

### Object-Oriented Programming (OOP)

- Encapsulation
- Abstraction
- Inheritance
- Polymorphism
- Composition vs. Inheritance
- Interfaces and Abstract Classes

### SOLID Principles

- **S** — Single Responsibility Principle
- **O** — Open/Closed Principle
- **L** — Liskov Substitution Principle
- **I** — Interface Segregation Principle
- **D** — Dependency Inversion Principle

### Design Patterns

The repository contains implementations and examples of commonly used design patterns.

**Creational Patterns**
- Factory Method
- Abstract Factory
- Builder
- Singleton
- Prototype

**Structural Patterns**
- Adapter
- Decorator
- Facade
- Proxy
- Composite
- Bridge

**Behavioral Patterns**
- Strategy
- Observer
- Command
- State
- Template Method
- Chain of Responsibility

## LLD Problems

The repository will also include implementations of common interview-oriented Low-Level Design problems, such as:

- Parking Lot
- Elevator System
- Library Management System
- Vending Machine
- Logging System
- Notification System
- Coffee Machine
- Tic-Tac-Toe
- Snake and Ladder

## Language

All implementations are primarily written in **Modern C++ (C++17/C++20)**.

## Purpose

The main purpose of this repository is to:

- Strengthen object-oriented design fundamentals
- Understand when and why to use different design patterns
- Practice writing clean, maintainable, and extensible C++ code
- Learn to translate requirements into classes, interfaces, and relationships
- Prepare for Low-Level Design and C++ software engineering interviews

> The focus is not just on making the code work, but on understanding the design decisions, trade-offs, and alternatives behind each implementation.
